### Item 10 — Hashcash 429 e2e gap (Phase 14 Plan 02)

`tests/integration/hashcash.e2e-spec.ts` (259 lines, 4 specs, all PASS) boots a live AppModule with only TrustScoreService / ProxyService / AuditRepository / PolicyEvaluatorService overridden. HashcashService + UsedNonceStore + GatewayMiddleware step 8 run live. Coverage:

1. Baseline score 0.5 < 0.7 → 200, no challenge headers.
2. Score 0.85 > 0.7 → 429 + `X-Hashcash-Challenge: <nonce>:4` + `Retry-After: 1` + body `{error:'proof_of_work_required', nonce, difficulty:4}`; proxy NOT invoked.
3. Client solves → resubmit → 200 (proxy reached).
4. Solution replay → 429 `proof_of_work_invalid` (UsedNonceStore single-use guard).

Env pinning at the spec head ensures deterministic difficulty=4 (~16 iterations, <1ms solve), keeping the spec fast and CI-safe.
